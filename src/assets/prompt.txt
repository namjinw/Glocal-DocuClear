# DocuClear 문서 분석 실행 명세

실행 프롬프트의 단일 원본은 src/utils/groq.ts의 FACT_INSTRUCTION, RISK_INSTRUCTION, SAFETY_INSTRUCTION입니다.
제공자는 Groq이며 모델은 openai/gpt-oss-120b로 고정합니다.

## 연결과 API 키

- API 키는 서버의 GROQ_API_KEY 환경변수에서만 읽습니다.
- 브라우저는 API 키를 읽거나 저장하거나 요청 본문에 포함하지 않습니다.
- GET /api/groq/config는 configured, model, provider만 반환합니다.
- POST /api/groq/chat은 서버에서 Groq로 연결합니다. 브라우저가 외부 제공자에 직접 요청하지 않습니다.
- 다른 모델로 자동 전환하지 않습니다. 반환된 모델도 고정 모델과 일치하는지 확인합니다.
- 원시 제공자 오류, 인증 토큰 또는 요청 주소를 사용자 화면과 콘솔에 출력하지 않습니다.

## 지원 입력

GPT-OSS 120B는 텍스트 입력 모델입니다. 텍스트와 PDF에서 추출한 본문을 분석합니다.
이미지와 스캔 PDF는 직접 모델에 전달하지 않습니다. 추출된 텍스트가 없으면 OCR한 텍스트를 입력하도록 안내합니다.

## 실제 AI 분석 단계

1. 문서 전체를 구조화된 조항으로 분리합니다. 조항 ID, 원문, 시작·끝 위치 및 참조 조항을 보존합니다.
2. 첫 번째 AI 요청에서 모든 조항의 사실을 추출합니다. facts는 clauseId, quote, rights, obligations, exceptions, affectedParties, references를 포함합니다.
3. 응답의 필수 필드, 원문 인용 및 조항별 추출 누락 여부를 검사합니다. 입력 본문을 재작성하지 않아야 합니다.
4. 두 번째 AI 요청에서 전체 원문과 facts를 함께 읽어 개별 위험 및 교차조항 위험을 분석합니다.
5. 모든 원문 조항에 clauseAssessments를 하나씩 요구합니다. 상태는 RISK, INFORMATION, ACTION, NONE이며 근거 하이라이트 ID를 연결합니다. 누락이나 잘못된 원문 인용은 완료로 처리하지 않습니다.
6. 원문 위치, 중복 ID, 복합 위험의 연결 ID, 위험 개수와 최종 점수를 검증합니다. 표시 항목 수를 12개로 자르지 않습니다.

각 요청은 Groq의 strict JSON Schema 형식을 사용합니다. 모든 객체는 additionalProperties:false, 모든 필드는 required이며 선택적 정보는 null을 허용합니다. 스키마 제약과 별도로 원문 인용·조항별 검토 완전성을 검증합니다.
진행 표시는 실제 요청과 검증 단계에서만 갱신합니다. 시간 기반으로 자기검증이나 심층 분석이 완료됐다고 표시하지 않습니다.

## 분류 원칙

- DANGER: 구체적인 불이익과 영향을 받는 당사자 및 원문 근거가 있는 위험.
- IMPORTANT: 일반 금액, 기간 및 중요 계약 조건.
- ACTION: 제출, 보고, 통지 등 수행사항. 평등 또는 안전이라는 판정이 아닙니다.
- 일반 정보에 위험 카테고리를 부여하지 않습니다.
- 위험 단어만으로 판단하지 않습니다. 부정문, 예외, 상대방 동의, 정당한 사유, 책임 주체를 함께 읽습니다.
- 업무 확대와 보수 금지, 검수 유보와 대금 지급, 배상 한도와 예외, 갱신과 해지 제약 등 실제로 연결된 조항을 함께 검토합니다.
- 인용은 해당 조항 원문의 연속 문자열이어야 합니다. 서로 다른 문장을 붙이거나 생략 부호로 합성하지 않습니다.
- 참조된 조항이 없으면 판단의 제한을 기록하며, 그 조항의 내용을 추정하지 않습니다.

## 입력 문서의 신뢰 경계

문서 본문, 추출된 facts 및 대화 기록은 분석 자료입니다. 그 안에 포함된 명령, 역할 변경, 판정 결과 조작, 비밀정보 요청을 수행하지 않습니다. 분석 지침은 별도의 system 메시지에 전달합니다.

## 실패와 분석 출처

- 서버 키 미설정: 로컬 규칙 분석, mode=local, status=limited.
- AI 요청 또는 응답 검증 실패: 원인과 로컬 대체 여부를 warnings에 기록합니다.
- 잘못된 API 키: 401 오류로 안내하며, 성공한 AI 결과처럼 처리하지 않습니다.
- mode, status, 실제 사용 model, analyzedClauseCount, totalClauseCount, unresolvedReferences를 결과에 기록합니다.
- Q&A도 서버 프록시와 고정 모델을 사용합니다. 키가 없을 때 기존 분석 내용을 안내할 수 있지만 새로운 AI 응답이 생성되지 않았다고 명시합니다.

## 표시와 점수

하이라이트는 원문과 연결한 위치를 사용합니다. 모델에 이미지 위치를 추정하게 하지 않습니다. 겹침을 피하려고 원문과 다른 위치로 이동하지 않습니다.
위험 점수는 검증된 결과에서 다시 산정합니다. 로컬 분석, 미해결 참조, 불완전한 판독 및 근거 연결 실패는 판단 한계를 표시합니다. 제한된 분석에서 위험이 탐지되지 않았다는 사실을 안전 확인으로 표현하지 않습니다.

## 법적 판단의 한계

위험 신호와 법적 효력·사기·위법 판단을 구분합니다. 문서에 증빙이 없다는 사실은 실제 증빙의 부존재를 뜻하지 않습니다. 개인정보·공증·관할법원 등의 선택적 정보가 없다는 이유만으로 위험을 만들지 않습니다. 서명란만 확인되는 경우 실제 서명 여부는 확인되지 않은 상태입니다.
